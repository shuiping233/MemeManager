## 三、最重要的功能演进主题

## 拖拽交互体系（Drag & Drop as first-class）

- **发布时间**：2026-07-10 起贯穿至 2026-07-24（此后仍有维护性修补）
- **重要版本**：`v1.0.0`、`v1.2.0`（分类拖拽排序）、`v1.7.10`、`v1.7.17`、`v1.8.0`~`v1.8.7`、`v1.10.6`
- **内容**：分类控件与图片控件全量可拖拽；分类拖拽重排序；图片拖入分类完成重分类与批量移动；编辑模式多选拖拽重排；向资源管理器/其他应用拖出（StorageFile 拖出为文件、老 QQ 拖拽发图）；拖入导入与重复检测；拖拽期间的浮窗抑制与插入占位消除。
- **评价**：这是本产品真正的"第一公民"能力，也是最耗心力的一条线——闪退治理走了"禁用外部拖拽 → 换方案 → `SetDataProvider`/自定义拖拽彻底修复"的完整弯路。"重复图片检查 + 统一的 move/置顶语义"体现了把交互升格为规则的成熟度。

## 常驻工具形态：托盘 + 快捷键 + 开机自启 + Full/Mini 双形态

- **发布时间**：2026-07-10 → 2026-07-31
- **重要版本**：`v1.0.0`、`v1.4.2`（开机自启）、`v1.8.7`（多开呼出既有实例）、`v1.11.0`~`v1.11.3`（Mini 模式）
- **内容**：托盘图标与左键呼出、全局快捷键与录制、注册表开机自启（含空格路径修复）、单实例与多开呼出、`334x117` Mini 浮窗（自定义标题栏、分类下拉、flyout、拖拽与粘贴、导入提示、强制置顶）、托盘菜单切换窗口模式、`--hidden` 启动。
- **评价**：把"表情包管理器"从一次性工具变成随系统常驻的输入法式助手。Mini 模式是这段最有价值的结构性演进（`MainPage` 抽离），也直接带来后续一系列"切模式刷新/焦点/置顶状态"的边界问题。

## 图片预览浮窗

- **发布时间**：2026-07-12 起
- **重要版本**：`v1.5.0`~`v1.5.4`、`v1.7.8`、`v1.7.10`、`v1.7.15`
- **内容**：鼠标悬停放大预览 + 标题；预览最大分辨率可配置（默认从更高档降到 640x480）；淡入淡出；浮窗渲染屏外/持续停留/拖拽期间弹出等一系列 bug 的连续修复；图像缓存及时释放；文件选择器打开时抑制浮窗。
- **评价**：单点功能做成了产品记忆点。代价是浮窗与拖拽、文件对话框、屏幕边缘的交互冲突轮番出现，也促使作者建立起"缓存要显式释放"的纪律。

## 内存与资源治理（与 WinUI3 泄漏长期对抗）

- **发布时间**：2026-07-11 → 2026-09-22（贯穿整个项目生命周期）
- **重要版本**：`v1.4.1`、`v1.6.0`/`v1.6.1`、`v1.7.2`、`v1.7.8`、`v1.12.6`、`v1.12.19`、`v1.13.0`、`v1.13.1`、`v1.13.4`
- **内容**：切分类内存优化 → 控件复用对抗图像缓存泄漏 → 关闭窗口后 GC/释放 GPU 纹理 → `XBindLeakFix` + 页面卸载 `StopTracking` + 禁用 bitmap 缓存 → 设置页改单例 → 隐藏窗口时单独释放分类控件 → 修 `--hidden` 启动后后台仍吃 CPU/GPU。
- **评价**：这是本项目最"苦"也最真实的一条主线。方案在"复用控件"与"及时释放"之间来回摆（`v1.7.2` 甚至 revert 了前一版的置空策略），最终收敛到"把可释放资源分级管理、按需重建"。它也是唯一贯穿到最后一版的持续议题。

## 设置与配置的可靠性 + 人可读性

- **发布时间**：2026-07-12 → 2026-08-18
- **重要版本**：`v1.5.0`、`v1.7.0`、`v1.12.0`、`v1.12.3`、`v1.12.5`、`v1.12.16`、`v1.13.1`
- **内容**：修"保存两次/逐字刷新"；JSON 加 indent + UTF-8 可读；配置写入去重（record 值相等）、切分类与存储路径防抖；关闭路径强制 flush 当前分类、刷新不覆盖当前分类；延迟保存的窗口尺寸在退出时立即落盘；数据目录不存在/非文件夹的兜底与诊断弹窗；退出设置时"没改关键项就不刷新"。
- **评价**：从"能存下"到"存得对、写得少、读得懂"。防抖 + 去重把写盘从"每输入一个字符一次"降到"停止输入后一次"，是典型的以量化为前提的优化。

## 批量 IO 性能与 UI 不阻塞

- **发布时间**：2026-07-26 → 2026-07-27
- **重要版本**：`v1.10.0`~`v1.10.7`（另见 `v1.12.0` 的写入去重）
- **内容**：`Parallel.ForEachAsync` 统一 IO 风格；导入/导出/删除并行化，导入 1000 张图的性能跃升；InfoBar 进度条显示进度且不阻塞主窗口；`BatchProgressHelper` 抽象；写入任务互斥（有写入时拒绝新任务/阻止重排序并弹窗）；全选阻塞修复。
- **评价**：把"能导入"提升为"导入得快且看得见进度"，同时明确承认并发写是风险区并用显式互斥挡住；`BatchProgressHelper` 说明作者在重复代码出现第二次时就做了抽象。

## 虚拟聚合视图「全部表情」

- **发布时间**：2026-07-26 → 2026-08-02
- **重要版本**：`v1.10.2`、`v1.10.4`~`v1.10.7`、`v1.12.1`

- **评价**：跨分类只读聚合的价值很高，作者对它的"只读边界"守得比较严，先把语义收窄再谈扩展，避免了后续大量状态不一致。

## 数据安全与输入校验

- **发布时间**：2026-08-03 → 2026-08-04
- **重要版本**：`v1.12.6`、`v1.12.7`、`v1.12.8`
- **内容**：`SafePath` 路径边界类（堵住分类名 `..` 目录逃逸的 Critical 问题）；引擎分类路径全量走边界校验；metadata 非法键过滤（拒绝路径逃逸与非图片扩展名条目）；图片扩展名白名单集中管理；非法分类名严格拒绝并弹窗（不再静默兜底为未分类）；存储路径拒绝相对路径与不存在路径（三入口统一校验 + 防抖 + 弹窗互斥）。
- **评价**：项目里技术含量最"硬"的一段。分类名直接参与文件系统路径，逃逸风险是真实存在的；这里同时完成了"集中白名单 + 单点校验 + 测试覆盖"，属于教科书式的收口。

## MVVM 架构现代化与消息机制

- **发布时间**：2026-08-02 → 2026-08-19
- **重要版本**：`v1.12.0`（#25 MVVM 重构）、`v1.12.18`（`WeakReferenceMessenger`）、`v1.12.16`~`v1.12.19`（Debounce utils）
- **内容**：从 code-behind 事件驱动迁移到 ViewModel + Command；`x:Bind` 优先；设置/关于/日志/反馈按钮收敛到 VM；Debounce 工具类统一窗口尺寸、存储路径、搜索框、切分类四处调用；退出流程改用 `WeakReferenceMessenger` 消息订阅；修掉"退出程序崩溃""频繁开设置页崩溃/泄漏"。
- **评价**：这是本项目唯一一次真正意义上的架构重构，收益是后续所有交互改动都能落在 VM 上；同时它把先前积累的"事件订阅/时序/防抖"类 bug 一并暴露出来，属于高风险高回报的一步。
